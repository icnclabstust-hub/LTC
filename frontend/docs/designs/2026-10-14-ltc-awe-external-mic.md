# 設計文件（DESIGN_DOC）：LIFF 錄音頁選擇外接麥克風

> Tier：B（暫定；改動經 ngrok 對外的 LIFF 服務）
> 流程豁免：老師 2026-10-12「以後測試不用等我認可，就是 try」；提案學生確認沿用，會議報告
> 提案學生：吳佳杰　　版本：草稿 v0.1（2026-10-14）

## 1. 需求（GD 步驟 1，2026-10-14 提案學生確認）

- **要解決什麼問題**：手機離說話的人太遠時收音不清楚，語音辨識錯字多；想測試外接麥克風能不能減少錯字。
- **誰會用**：提案學生做測試；之後照護員也可能把麥克風接在手機上收音。
- **不做會怎樣**：只能用手機內建麥克風，離得遠就聽不清楚。
- 決定：
  1. 只支援 Android＋Chrome；麥克風接 Type-C（例如 RODE Wireless Micro）。
  2. 錄音頁新增「麥克風」下拉選單，列出網頁偵測到的麥克風，照護員點選後就用它錄音。
  3. 不論是一個還是多個發射器、單聲道還是雙聲道，都一律**合成一路收音**，跟手機內建麥克風一樣；說話人仍靠聲紋分匿名代號（不用聲道判斷說話人）。
  4. 回音消除、降噪、自動增益維持開啟，不另外比較。
  5. 直接在 LIFF 的錄音頁實測。

## 2. 現況（GD 步驟 2）

| 項目 | 現況 | 缺口 |
|---|---|---|
| 選擇麥克風 | `recorder.open()` 的 `getUserMedia` 沒有指定裝置，用系統預設的那一支 | 沒有列出裝置、沒有選擇的地方；不知道實際用的是哪一支 |
| 聲道 | `getUserMedia` 要求 `channelCount: 1`，但只是「希望」，不保證；`recorder-worklet.js` 只取第一個聲道 `inputs[0][0]` | 外接麥克風設成雙聲道（左右各一個發射器）時，**第二個發射器的聲音會被丟掉** |
| 錄音中拔掉麥克風 | 沒處理 | 拔掉後可能一直送靜音，使用者不知道 |
| 記住選擇 | 已有 `localStorage` 存「目前角色」的寫法（`ACTING_ROLE_KEY`） | 可沿用 |
| 本 repo 其他實作 | 沒有 `enumerateDevices`／`deviceId` 的程式 | — |

- 現成做法：瀏覽器內建 `navigator.mediaDevices.enumerateDevices()` 可以列出麥克風；`devicechange` 事件在插拔時觸發。不需要新增套件。
- 限制：使用者還沒允許麥克風之前，Chrome 列出的裝置**沒有名稱**。另外，Android Chrome 會怎麼列出 USB 麥克風（名稱、數量），要實測才知道。

## 3. 方案比較

| | 方案 A：下拉選單＋指定裝置（**採用**） | 方案 B：不給選，只顯示目前用的是哪一支 |
|---|---|---|
| 做法 | 列出麥克風供選擇；錄音時用 `deviceId: {exact}` 指定 | 沿用系統預設；錄音時顯示麥克風名稱，要換就插拔 |
| 優點 | 符合需求；同時接了多支時也能選 | 改動最少 |
| 缺點 | 程式較多；要處理選過的麥克風被拔掉的情況 | Android 不一定會自動切到 USB 麥克風，無法保證用到外接麥克風 |

兩個方案都需要修正聲道：worklet 改成**把所有聲道平均成一路**。這樣雙聲道時兩個發射器的聲音都會保留；單聲道時結果跟現在一樣。

## 4. 設計（方案 A）

### 4.1 錄音頁（錄音卡片，「確認錄音」按鈕上方）

```
麥克風：[ 手機預設麥克風        ▼ ]  [重新偵測]
        （USB 麥克風名稱…）
提示：剛插上的麥克風沒出現時，請按「重新偵測」。
```

- 選項第一項固定是「手機預設麥克風」（不指定裝置，等於現在的行為），其後列出 `enumerateDevices()` 回報的每個 `audioinput`（不含 `default`、`communications` 這類別名）。沒有名稱時顯示為「麥克風 1、2…」，並提示「按『確認錄音』允許麥克風後會顯示名稱」。
- 插拔時（`devicechange`）自動更新選項；也可以按「重新偵測」手動更新。
- 選擇存在 `localStorage`（`xiaozhao.micDeviceId`），只存在這支手機的瀏覽器裡；下次開啟頁面時，如果那支麥克風還在，就預設選它。
- **錄音中不能切換麥克風**（下拉選單鎖住，跟住民切換一樣）。要換麥克風，先停止錄音。
- 錄音中顯示「使用中：<麥克風名稱>」（取自 `track.label`）。

### 4.2 開始錄音

```js
// 示意：選了特定裝置才指定
audio: { deviceId: micId ? { exact: micId } : undefined,
         echoCancellation: true, noiseSuppression: true, autoGainControl: true }
```

- 不再要求 `channelCount: 1`，由 worklet 自己合成一路，避免 Chrome 拒絕雙聲道的麥克風。
- 選的麥克風已經不在（`OverconstrainedError`／`NotFoundError`）時，提示「找不到選擇的麥克風，已改用手機預設麥克風」，改用預設麥克風錄音，並把下拉選單改回預設。

### 4.3 聲道合成（`recorder-worklet.js`）

- 每個取樣點把 `inputs[0]` 所有聲道平均後，再降頻到 16 kHz；`AudioWorkletNode` 設 `channelCount: 2`、`channelCountMode: 'max'`，讓雙聲道的訊號能完整進來。

### 4.4 錄音中拔掉麥克風

- 監聽麥克風音軌的 `ended` 事件：出現時停止錄音，並顯示「麥克風已中斷，錄音已停止。請確認麥克風連線後重新開始。」。不自動切回手機麥克風，以免使用者不知道已經改用手機收音。

### 4.5 不改的部分

- 伺服器、資料庫、送後端的 JSON 都不改。（之後如果要分析錯字和麥克風的關係，再考慮記錄用了哪一支麥克風；本次不做。）

## 8. 實測問題與修正（2026-10-14，提案學生確認：1 做、2 選 A）

### 8.1 實測結果

同一份文稿（`external-mic-script.md`），手機內建麥克風（住民A）與 RODE（Mic1）各錄三輪：

| | 手機 | RODE |
|---|---|---|
| 字錯誤率（CER，`mic_cer.py`） | 17.9% | 26.9% |
| 說話音量（音框 RMS 第 90 百分位） | 約 -17 dBFS | 約 -26～-31 dBFS |
| 切句 | 每輪 4 句，正常 | 每輪 1 句；第 54 輪第一句長 21 秒，因為 VAD 單句上限約 20 秒才被強制切斷 |

- **原因**：RODE 的音量小 9～14 dB，Silero VAD 在這個音量下分不清停頓。窗的位置只差 8 毫秒，切句結果就會改變（同一段有時切 2 段、有時切 3 段）。
  - 把音量拉到手機的水準後，切句就穩定了；
  - 調 VAD 門檻沒有用（調低會切更少，調高也不穩定）。
- **另外**：第一輪結尾的「小照請回答」被 ASR 轉成「小套請回答」。KWS 有聽到，所以結束原因是對的；但文字裡找不到關鍵詞，這句就留在逐字稿裡。

### 8.2 修正

| 方案 | 做法 | 結論 |
|---|---|---|
| **A（採用）** | 伺服器自動放大：依最近說話時的音量放大到手機的水準 | 任何麥克風都適用，照護員不用設定 |
| B | 錄音頁加音量滑桿 | 照護員不知道要調多少 |
| C | 在 RØDE App 調高增益 | 只適用 RODE |

- **`autogain.py`**：
  - 只用 VAD 判定為「說話中」的片段估計音量：最近 20 秒、30 毫秒音框 RMS 的第 90 百分位，全零的音框不計；
  - 累積 2 秒說話後才開始放大；
  - 放大量 = -18 dBFS 減去估計的音量，介於 0 到 24 dB 之間（只放大、不縮小）。
- **套用範圍**：放大後的音訊同時用在 KWS、VAD、ASR、聲紋，以及給督導回聽的錄音；放大量改變超過 1 dB 時寫入日誌。
- **設定**：`AUTO_GAIN`（預設 1）。`SessionProcessor(auto_gain=False)` 預設關閉，因為單元測試的假 ASR 是用振幅辨識句子。
- **寬鬆刪除關鍵詞**：KWS 已聽到喚醒詞或結束詞，但文字裡找不到時，刪掉開頭的「〇〇你好」、結尾的「〇〇請回答」（〇〇 是 0～2 個任意漢字）。KWS 沒聽到就不刪。
  - 既有測試 `test_kws_wake_without_keyword_in_text_falls_back_to_segment_level` 的預期結果因此從「小草你好第二個問題」改成「第二個問題」。

### 8.3 驗證

- 單元測試：139 項全過（新增 `test_external_mic.py` 6 項）。
- 用真實的 Silero VAD 模擬即時串流（每 0.5 秒一段，窗位移 0／128／256／384 各跑一次，一次性腳本）：

  | 錄音 | 原始：段數／最長 | 自動放大：段數／最長 |
  |---|---|---|
  | RODE 第 52 輪 | 5／5.2 秒 | 5／5.0 秒 |
  | RODE 第 53 輪 | **1～2／16.4 秒** | **6／4.9 秒** |
  | RODE 第 54 輪 | 4～6／6.5 秒 | 6～7／4.9 秒 |
  | 手機三輪 | 5／7.6 秒 | 不變（放大 0 dB） |

  RODE 最後估計的放大量是 +9 dB。
- 待提案學生用同一份文稿再錄一次 RODE，比較切句和 CER。

## 9. 更正與第二次修正（2026-10-14，提案學生確認）

### 9.1 更正：先前的「RODE」錄音其實是手機麥克風

- 提案學生選的是下拉選單裡的 **Speakerphone**，「使用中：Speakerphone」，也就是手機內建麥克風。對著手機說「小照你好」有反應，對著 RODE 說沒有反應。
- 所以第 8.1 節「RODE」那一欄，其實是**手機在不同條件下**（距離、電風扇）錄的。
  - 「RODE 字錯誤率 26.9%」「RODE 音量小 9～14 dB」都不成立，不能當作外接麥克風的結果。
  - 自動放大對小聲的輸入仍然有效（第 8.3 節的驗證數據不變），但「外接麥克風比較小聲」這個前提不成立。
- **推測的原因（尚未證實）**：Android Chrome 開著回音消除時，會用「通話模式」收音。通話模式不使用 Type-C 錄音設備，所以 RODE 不會出現在選單裡，選「手機預設麥克風」也用不到。

### 9.2 修正

| | 問題 | 修正 |
|---|---|---|
| 外接麥克風模式 | 選單裡沒有 RODE | 錄音頁新增「使用外接麥克風」勾選框（記在手機瀏覽器）。勾選時不指定裝置，並**關閉回音消除、降噪、自動增益**，讓 Android 改用插著的外接麥克風；麥克風選單變灰；「使用中」加註「（外接麥克風模式）」。這改變了第 1 節第 4 點的決定，提案學生已同意。 |
| A：誤觸發 | 開著電風扇時，5 次錄音共 13 輪，其中 10 輪是空輪（KWS 誤報喚醒詞、沒有人說話、3 秒後因靜音結束） | 沒有對應句子的喚醒詞，**前 2 秒內要有 VAD 切出的語音**才開輪，否則忽略並寫入日誌 |
| B：結束詞卡住 | 說了「小照請回答」，但風扇聲讓 VAD 一直判定在說話，這一輪約 35 秒後才結束 | 聽到結束詞後，VAD 仍判定在說話超過 **1.5 秒**，就強制斷句（VAD flush）並結束本輪。已用真實 VAD 確認，強制斷句後仍能正常繼續切句。 |
| C：放大量估計 | 改用中位數 | **暫不做**，等用到 RODE 後看實際音量再決定 |

- 測試：141 項全過，新增 2 項。這 2 項在關掉 A、B 修正時會失敗，確認測試抓得到問題。
- 待提案學生實測：
  1. 勾選外接麥克風模式後，對著發射器說話有沒有反應（把手機放遠或蓋住手機的麥克風）；
  2. 開著電風扇時，空輪是否減少、「小照請回答」是否在 1.5 秒內結束；
  3. 用到 RODE 之後，照文稿重新比較字錯誤率。

## 10. 外接麥克風模式實測與第三次修正（2026-10-14）

- **外接麥克風模式有效**：勾選後測了 5 次，都由 RODE 收到「小照你好」；開著電風扇再測 5 次也一樣。第 9.1 節的推測（回音消除會讓 Chrome 改用通話模式）得到證實。
- **新問題**：只說「小照你好」時，喚醒詞本身被 ASR 轉成「老趙你好」「照你好」「照你也好」，又被當成這一輪的第一句。10 輪中有 4 輪出現這種情況。
  - 原因：這些寫法不符合 `WAKE_PATTERN`（要求開頭是「小／曉／筱」），也不符合寬鬆刪除的條件。
  - 修正：一輪的**第一句**、在開輪後 **3 秒內**、且整句只有「〇〇你好／〇〇你也好」（〇〇 是 0～2 個漢字）時，不列入逐字稿，並寫入日誌。
  - 一輪中間的「阿公你好」不受影響。
  - 既有測試 `test_declined_consent_never_computes_voiceprint` 原本用「你好」當作開輪後的句子，這和測試目的（聲紋同意）無關，改成「問題」。
- **音量觀察**：外接麥克風模式關掉了手機的自動增益，存下來的喚醒詞音量只有約 -43 dBFS（手機約 -17）。
  - 自動放大要累積 2 秒說話才開始，最多放大 24 dB，所以每次錄音最初的幾句會比較小聲。
  - 要等照文稿實測後，看切句和字錯誤率，再決定是否調整（例如外接麥克風模式改由網頁先固定放大）。
- 測試：145 項全過，新增 4 項。

## 11. 外接麥克風模式保留降噪（2026-10-14，提案學生確認試做）

- **問題**：外接麥克風模式關掉了 Chrome 的降噪，背景聲（約 -50 dBFS）一直存在，經自動放大後送進 VAD，VAD 一直判定在說話，整輪變成 17～21 秒的一段。
  - 同一段音訊從頭重跑時，VAD 可以正常切句；
  - 在前面接上 20 秒背景聲再跑，就切不開。
- **修正**：外接麥克風模式只關回音消除與自動增益，**保留降噪**（`noiseSuppression: true`）；勾選框文字同步修改。
