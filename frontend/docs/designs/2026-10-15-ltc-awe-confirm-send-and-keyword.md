# 設計文件（DESIGN_DOC）：N0v3 上線、低信心問題由照護員確認、結束詞改「小照回答」、移除麥克風選單

> Tier：B（改變服務的意圖模型、送後端的條件、切輪關鍵詞與錄音頁）
> 流程豁免：老師 2026-10-12「以後測試不用等我認可，就是 try」；提案學生確認沿用，會議報告
> 提案學生：吳佳杰　　版本：草稿 v0.1（2026-10-15）

## 1. 需求（GD 步驟 1，2026-10-15 提案學生決定）

### 1.1 意圖模型換成 N0v3

- **依原標準（`n0-rhetorical-retrain` 第 4.2 節）未通過**：
  - care7ctx 交叉驗證 78.3%，標準為 ≥ 78.6%；
  - care7 為 90.4%，標準為 ≥ 90.5%。
- **提案學生決定更換**，理由：
  - 原標準以 AI 生成資料為主，偏樂觀，也與實際說話方式不同；
  - 差距落在三個 seed 的波動範圍內（N0v3 為 77.5～79.5%，N0 為 78.8～81.2%）；
  - 實際使用的指標進步：10/14 錄音 53 句 81.1% → 84.9%、反問誤送 3/10 → 1/10、抱怨口氣對照句 6/10 → 8/10。
- 於 10/19 會議報告，並提出「標準改以實際錄音為主」的建議，請老師確認。
- 預取門檻維持 0.9。

### 1.2 低信心的問題由照護員確認後才送出

- **適用範圍**：意圖屬於規範詢問、服務請求、身體不適陳述（送後端的三類）。

  | 信心 | 處理 |
  |---|---|
  | ≥ 0.9 | 照舊自動送出 |
  | 0.5～0.9 | 跳出確認視窗，列出這些項目，讓照護員勾選後送出 |
  | < 0.5 | 不送出，也不詢問 |

- 照護員按「×」或沒有確認：
  - 項目存到「我的案件」；
  - 下方分頁「我的案件」顯示「❗」；
  - 「我的案件」中以醒目顏色標示這些未確認的項目，之後仍可送出。
- **LIFF 手動打字提問**：也判定意圖，照同樣規則（≥ 0.9 送出、0.5～0.9 確認、< 0.5 不送）（提案學生 2026-10-15）。
- **LINE 聊天室文字提問**（提案學生 2026-10-15 定的使用規則）：**只回答規範詢問並附上出處；醫療、用藥、補助金額相關都轉督導；其餘皆不回答**。不需要照護員確認。
  - 醫療、用藥、補助金額的判斷原本只寫在模擬後端（`MockBackend` 的 `_HUMAN_ONLY`），接上後端組的後端後就由後端決定；改由本服務在 LINE 收到時先比對，不論後端為何都成立。

### 1.3 結束詞改成「小照回答」

- 只偵測「小照回答」；**「小照請回答」不再能結束一輪**（不設過渡期）。
- 用提案學生的錄音重新測試開輪與誤觸發（2026-10-15 同意）。

### 1.4 移除麥克風下拉選單

- 錄音頁只留「使用外接麥克風」勾選框。
- **勾選框的作用**（2026-10-14 實測）：
  - 勾選後關閉回音消除、保留降噪，Android 會自動使用插著的 Type-C 麥克風，沒插就用手機麥克風；
  - 不是「偵測」或「鎖定」某一支麥克風（Android Chrome 列不出外接麥克風）。
- 說明文字改為：「插上外接麥克風後勾選；勾選後，插著外接麥克風就用外接麥克風，沒插就用手機麥克風」。
- 錄音中拔掉外接麥克風時，停止錄音並提示（10/14 已實作）。
- 之前存在瀏覽器的麥克風選擇不再使用。

## 3. 方案比較（1.2 節：確認的時機）

| | 方案 A：輪結束時一次確認（**採用**） | 方案 B：每句判定後立即詢問 |
|---|---|---|
| 做法 | 一輪結束，跳出視窗列出這一輪所有未達門檻的項目 | 每句判定完就跳出詢問 |
| 優點 | 不打斷錄音中的對話；一次處理 | 較即時 |
| 缺點 | 回答晚一點 | 錄音中頻繁跳窗，干擾照護 |

## 4. 設計

### 4.1 N0v3

`config` 的 `N0_MODEL_DIR` 預設值改為 `exported_ctx_care7/N0v3_s42/model`；回滾時在 `.env` 設回 N0。

### 4.2 待確認的項目

- 新狀態 `needs_confirm`（`MEDICAL` 關鍵詞維持現行嚴格規則，含「病」；提案學生未要求修改）：
  - 錄音：`turns.intents` 的項目狀態；
  - 打字：`text_questions.status`；
  - LINE：`line_cases.status`。
- **錄音**：
  - 輪結束時，三類、信心 0.5～0.9 的問句或意圖，不送出，標為 `needs_confirm`；
  - ≥ 0.9 的照舊（預取或送出）；
  - 這一輪的回答顯示已送出的項目，以及「有 N 個問題等你確認」。
- **確認視窗**（錄音頁）：輪詢到有 `needs_confirm` 時跳出，列出項目（問題文字與意圖），預設不勾選。
  - 〔送出所選〕：送後端，回答併入該輪；
  - 〔×〕：保留為 `needs_confirm`。
- **API**：
  - `GET /api/my/unconfirmed`：列出照護員未確認的項目；
  - `POST /api/unconfirmed/confirm`：`{source, id, item, send: true|false}`，`send=false` 改為 `dismissed`，不再提醒。
- **我的案件**：
  - 分頁標籤有未確認項目時顯示「❗」；
  - 頁首列出未確認項目（醒目底色），可送出或標為不用。
- **LIFF 打字提問**（提案學生 2026-10-15）：也判定意圖，與錄音相同的規則。
  - 三類且 ≥ 0.9：送出；
  - 三類且 0.5～0.9：跳出與錄音相同的勾選確認視窗；
  - 其他：不送出，不提供「仍要送出」；
  - 每則打字提問不論是否送出，都記錄在「我的案件」。
- **確認視窗預設不勾選**：照護員勾選要送的題目後按〔送出勾選的問題〕（提案學生 2026-10-15）。視窗只決定是否送後端，不影響逐字稿、說話人代號與確認紀錄，錄音也不中斷。
- **LINE 文字提問**（依序判斷）：
  1. 含醫療、用藥、補助金額的關鍵詞（沿用 `_HUMAN_ONLY`：藥、醫、病、診、補助、金額、多少錢）→ 直接轉督導，回覆「這個問題已轉給督導，督導回覆後會通知你。」，不送後端（即使意圖判為規範詢問）；
  2. 意圖為規範詢問（不論信心）→ 送後端，回答並附上出處；後端拒答時照舊轉督導；
  3. 其餘 → 不回答（不送後端、不轉督導）；LINE 案件記為 `not_answered`，「我的案件」顯示「小照在 LINE 只回答規範查詢」。
- **出處**：`BackendResult` 新增 `citations`。
  - `HttpBackend` 取 ③ 的 `citations`（`title`、`article`）；
  - LINE 回覆在回答後加「出處：…」；
  - LIFF 回答也顯示出處。

### 4.3 小照回答

- `keywords.txt`：`x iǎo zh ào h uí d á :2.0 #0.2 @小照回答`（移除「小照請回答」）。
- `ANSWER_KEYWORD = "小照回答"`。
- `ANSWER_PATTERN`：`_ZHAO＋「回答」`，中間不接受「請」。
- 寬鬆刪除改為結尾「〇〇回答」（KWS 已聽到結束詞時）。
- 說明文字一併修改：LINE、使用說明、錄音頁、錄音前告知、串接說明。
- **測試**：
