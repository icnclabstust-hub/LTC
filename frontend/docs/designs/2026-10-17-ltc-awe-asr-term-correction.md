# 設計文件（DESIGN_DOC）：語音辨識照護用詞修正與「前後文衝突」提醒

> Tier：B（改變逐字稿與送後端的文字）
> 流程豁免：老師 2026-10-12「以後測試不用等我認可，就是 try」；提案學生確認沿用，會議報告
> 提案學生：吳佳杰　　版本：v1.0（2026-10-17，提案學生確認）
> 前置：`2026-10-17-ltc-awe-three-speaker-script.md`（三人實測：「復健」6 次全轉成「附件」）

## 1. 背景與問題（GD 步驟 1，2026-10-17 提案學生確認）

- **要解決什麼問題**：語音辨識把照護用詞轉錯，造成三個後果：
  - 逐字稿難讀；
  - 意圖判錯；
  - 送到後端的問題不正確，例如「附件師」查不到復健相關的規定。
- **誰會用**：
  - 照護員、督導：看逐字稿、確認紀錄；
  - 意圖模型、後端：收到的文字。
- **不做會怎樣**：照護員要在確認紀錄逐字修改；後端可能因用詞錯誤而答錯或查不到。
- **另一類錯誤**：「很痛」聽成「不痛」這類意思相反的錯字無法自動修，只能提醒人去看（提案學生 2026-10-17：前後文衝突時才提醒）。

## 2. 目標與非目標

- **目標**：
  1. 語音辨識轉完之後，依「照護用詞對照表」與前後文條件把錯字換成正確的詞；
  2. 前後文衝突時，在確認紀錄標示「⚠ 可能聽錯，請確認」（只提醒、不改字）；
  3. 錄音模式與今日狀況回報都套用；
  4. 保留語音辨識原文，改錯時看得出來、可以還原。
- **非目標**：
  - 不換語音辨識模型（transducer 加自訂詞列為方案 B 比較，不做）；
  - 不修「意思相反」的錯字，只提醒；
  - 不修通用字與性別同音字（她／他、濕／溼、紀／記、痠／酸、喔／哦）；
  - 不用確認紀錄訓練模型（同意書未涵蓋此用途，見第 9 節）。

## 3. 現況與重用（GD 步驟 2，2026-10-17）

- **錯誤組合**（照文稿唸的錄音 134 句，字錯誤率 21.9%）：

  | 錯誤組合 | 次數 |
  |---|---|
  | 阿嬤 → 阿媽 5、蛤蟆 3、媽媽 2、俺媽、藍冒、阿罵、然後 | 14 |
  | 復健 → 附件 5、附近 1 | 6 |
  | 住民 → 富明、著明 | 2 |
  | 營養品 → 著樣品；尿布 → 尿不、房子；事件紀錄 → 是墊鋪；血壓 → 血價；探視 → 看視；機構 → 雞乎 | 各 1～2 |

  同學模擬對話（tk、sp）的人工逐字稿本身有錯字，不採用。
- **重用**：
  - 服務裡關鍵詞的寬鬆比對：限定位置的規則比對，寫法相同；
  - `mic_cer.py`：正規化與字錯誤率；

- **套件**：
  - 目前的 Paraformer（sherpa-onnx 1.13.8）不支援自訂詞，只有 transducer 類模型支援；
  - pycorrector（Apache-2.0）支援自訂對照表，但主要靠大型語言模型判斷。
- **專有名詞來源**（提案學生 2026-10-17 決定，三個都用）：
  1. 衛福部《長期照顧服務申請及給付辦法》附表四照顧組合表等長照名詞；
  2. 訓練資料（care7、care7ctx）統計的照護常用詞；
  3. 上面的錯誤組合。

## 4. 方案比較

| | **方案 A：規則對照表（採用）** | 方案 B：transducer 模型加自訂詞 | 方案 C：pycorrector 對照表＋語言模型 |
|---|---|---|---|
| 做法 | 轉完後，符合前後文條件才換字 | 換成支援自訂詞的模型，轉的時候提高清單詞彙的分數 | 對照表產生候選，再用語言模型判斷要不要換 |
| 前後文條件 | 可以精確指定（例：「附件」後接「師、室、做」） | 不行，只能加分；加太多會在不相干處轉出該詞 | 由語言模型判斷，無法逐條控制 |
| 能修的錯 | 只有清單上、出現過的錯誤組合 | 清單詞彙在各種說法下都可能轉對 | 比 A 多一些 |
| 要重新驗證 | 換字有沒有改錯 | 字錯誤率、延遲、依每個字時間補標點等全部重測 | 改錯率；語言模型很大、載入慢 |
| 成本 | 小；無新依賴 | 大：換模型 | 中：新依賴、模型檔大 |

**選定方案 A**（提案學生 2026-10-17）：成本小、可以逐條審閱、改錯時可以追查是哪一條規則。

## 5. 系統設計

### 5.1 對照表（`src/xiaozhao/resources/asr_corrections.csv`）

| 欄位 | 說明 | 例 |
|---|---|---|
| 錯字 | 語音辨識的錯誤寫法 | 附件 |
| 正確 | 換成的詞 | 復健 |
| 前文 | 錯字前面要符合的規則（空白表示不限） | |
| 後文 | 錯字後面要符合的規則 | `師\|室\|做\|課` |
| 來源 | 錯誤組合／衛福部／訓練資料 | 錯誤組合（三人實測 6 次） |
| 審閱 | OK／改（提案學生） | |

- 由 AI 草擬，提案學生審閱；只載入「審閱」為 OK 的列。
- 前文和後文只看同一句，最多前後 4 個字。
- 例：
  - 「蛤蟆／俺媽／藍冒／阿罵」在句首，或前面是「跟、幫、說」→「阿嬤」；
  - 「阿媽」→「阿嬤」（統一寫法）；
  - 「媽媽」不換，因為可能真的在說媽媽。

### 5.2 前後文衝突提醒

只提醒、不改字。以下三種情形任一成立，就在該句標記 `review_flag`：

| 衝突 | 例子 | 判斷 |
|---|---|---|
| ① 同一句中，否定的症狀詞和不舒服的詞同時出現 | 「腰還是不痛，坐久了就受不了」 | 否定詞＋症狀詞（不痛、不暈、沒有發燒…）與難受、受不了、很不舒服、痛到… 同時出現 |
| ~~② 句子說沒事，意圖模型卻判成身體不適~~ | — | **已拿掉**（見第 10 節）：N0 對提到症狀的句子幾乎都判身體不適，不衝突句誤標 6/10 |
| ③ 同一輪前後句矛盾 | 前句「阿嬤說腰很痛」、後句「腰不痛」 | 同一輪內同一症狀詞，前面肯定、後面否定；有時間詞（這句「現在、已經…」或前句「剛剛、昨天…」）算好轉，不提醒 |

- 症狀詞、否定詞、不舒服的詞：放在 `asr_corrections.csv` 之外的 `review_terms.csv`，同樣由 AI 草擬、提案學生審閱。
- 限制：整句只有「不痛」、沒有其他線索時不會提醒。

### 5.3 資料流

```
語音辨識原文 → 去掉喚醒詞／結束詞 → 對照表換字 → 意圖判斷、送後端、逐字稿
                                       └→ 衝突檢查（看換字後的文字與意圖）→ review_flag
```

- 換字放在去掉關鍵詞之後、意圖判斷之前，所以意圖模型和後端拿到的都是修正後的文字。
- 今日狀況回報：轉文字後同樣換字、檢查衝突。

### 5.4 資料模型

- `utterances` 新增：
  - `asr_text TEXT`：語音辨識原文（換字前）；
  - `review_flag TEXT`：衝突原因，無則 NULL。
- 確認紀錄的 `doc` 每句加上 `asr_text`、`review_flag`（JSON，不改 schema）。
- `daily_reports` 新增 `asr_text TEXT`。
- 用既有的 `_add_column` 補欄位，舊資料為 NULL。

### 5.5 介面

- 確認紀錄：
  - 被換過字的句子，在旁邊顯示「原文：…」（小字）；
  - 有 `review_flag` 的句子，顯示「⚠ 可能聽錯，請確認」與原因。
- 錄音頁即時逐字稿：同樣顯示 ⚠。
- 無新增 API。

### 5.6 日誌

- 每次換字記錄規則編號，供統計規則被用了幾次、是否改錯。
- 日誌不記錄整句內容。

## 6. 安全與隱私

- 只多存語音辨識原文，保存期限與逐字稿相同（未確認 7 天、確認後最長 90 天）。
- 不新增對外介面，資料不離開服務。
