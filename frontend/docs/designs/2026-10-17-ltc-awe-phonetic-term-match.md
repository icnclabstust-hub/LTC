## 1. 背景與問題（GD 步驟 1，2026-10-17 提案學生確認）

- **要解決什麼問題**：同一個照護用詞，每次錄音都出現新的錯法。例如鼻胃管已出現鼻味管、鼻尾管、鼻位管、移位管四種；規則對照表逐條補，補不完。
- **誰會用**：
  - 照護員、督導：看逐字稿；
  - 意圖模型、後端：收到的文字。
- **不做會怎樣**：每次發現新錯法都要人工補規則；沒補到的錯字留在逐字稿與送後端的問題裡。
- **提案學生的決定**：
  1. 比對到之後兩段式：讀音非常接近的 3 個字以上直接換，其他只提醒；
  2. 讀音只允許**差聲調**（聲母、韻母不同的不算）；
  3. 用詞清單只放長照會用到的詞；
  4. 器材與醫學名稱從公開資料整理。

## 2. 目標與非目標

- **目標**：
  1. 在規則對照表之後，用讀音（不看聲調）比對長照用詞清單；
  2. 3 個字以上的用詞：讀音相同就直接換字（保留原文）；
  3. 2 個字的用詞：只提醒「可能是：〇〇」，不改字。
- **非目標**：
  - 不取代規則對照表：聲母、韻母不同的錯法（部件→復健、出壇→抽痰）仍靠對照表；
  - 不放寬到聲母、韻母相近；
  - 不放整份醫學名詞；
  - 不改語音辨識模型。

## 3. 現況與重用（GD 步驟 2，2026-10-17 提案學生確認）

- **已蒐集的錯誤組合 53 組**：

## 4. 方案比較

| | **方案 A：拼音（不看聲調）完全相同（採用）** | 方案 B：A＋用 jieba 判斷詞的邊界（2 字） | 方案 C：允許聲母、韻母相近 |
|---|---|---|---|
| 做法 | 片段的拼音去掉聲調後和用詞完全相同才算 | 2 個字的比對結果要剛好落在詞的邊界上才提醒 | 例：bu／fu、chu／chou 算相近 |
| 能抓到 | 20/53 組 | 比 A 少（漏掉「傳息」） | 更多 |
| 正確句子誤中 | 3 字以上 0；2 字提醒 8/1179 | 2 字提醒 5/1179 | 會大幅增加 |
| 依賴 | pypinyin | pypinyin＋jieba（含詞典） | pypinyin |
| 結論 | 採用 | 效益不足，不採用 | 提案學生決定不做 |

**選定方案 A**：最簡單；3 個字以上不誤換；2 個字只提醒、不改字，誤報 0.7% 可以接受。

## 5. 系統設計

### 5.1 比對

- 讀入 `care_terms.csv` 中審閱為 OK 的用詞，依「去掉聲調的拼音」建立索引。
- 對每一句（規則對照表換字之後），由長到短、不重疊地檢查每個片段：
  - 片段和用詞拼音（不看聲調）相同、但字不同；
  - 片段本身不是清單中的用詞，也不在已經正確出現的用詞裡面。
- 處理：
  - 用詞 ≥ 3 個字 → 直接換字，記為規則「讀音：鼻胃管」；原文存在 `asr_text`（與對照表共用）；
  - 用詞 2 個字 → 不改字，加上提醒「可能是：復健」（`term_hint`）。
- 多音字依 pypinyin 的預設讀音；不看聲調，所以聲調讀錯不影響。

### 5.2 資料流

```
語音辨識原文 → 去掉關鍵詞 → 規則對照表換字 → 讀音比對（≥3 字換字、2 字提醒）→ 意圖判斷 → 衝突提醒 → 逐字稿、送後端
```

### 5.3 資料模型

- `utterances` 新增 `term_hint TEXT`（「可能是：〇〇」，可多個，以「、」分隔）。
- 確認紀錄每句帶 `term_hint`，督導修改後保留。

### 5.4 介面

- 確認紀錄與即時逐字稿：顯示「💡 可能是：復健」，樣式和「⚠ 可能聽錯」區分。
- 被讀音比對換過字的句子，同樣顯示「原文：…」。

### 5.5 設定

- `PHONETIC_MATCH=1`（服務預設開、測試預設關）。

## 6. 安全與隱私

- 只多存提醒文字，保存期限與逐字稿相同。
- 不新增對外介面。

## 7. 測試策略

| 項目 | 資料 | 標準 |
|---|---|---|
| 抓到同音錯法 | 已蒐集的 20 組讀音相同或只差聲調的錯誤組合（放進句子） | 3 字以上全部換對；2 字全部提醒 |
| 不誤換 | care7ctx＋care7 1179 句 | 換字 0 句；2 字提醒 ≤ 1% |
| 不影響規則對照表 | 既有換字、衝突提醒的測試 | 全過 |
| 手機實測 | 新文稿（含沒看過的同音錯法機會較高的用詞） | 顯示「原文」與「💡 可能是」 |

- 限制：錯誤組合來自少數朗讀者，涵蓋率會隨更多錄音改變。
