# 小照 LINE Bot＋LIFF：後端串接說明

> 給：後端組（吳明叡）
> 來自：吳佳杰，2026-10-13（2026-10-14 更新）
> 對應程式：`src/xiaozhao/`（隨附 zip）；設計文件：`2026-10-08-ltc-awe-liff-recording-and-line-cases.md`
> 狀態：本服務預設接**模擬後端**（`BACKEND_MODE=mock`）；2026-10-14 起可依後端組 API 合約串接（`BACKEND_MODE=http`，第 3 節）。本文列出本服務會送什麼、期待收到什麼，以及需要後端組決定的事項（第 4 節）；欄位名稱都可以調整。

> **2026-10-19 更新：前後端已合併到同一個 repo 並完成串接**，以 `docs/designs/2026-10-19-xiaozhao-fe-be-integration.md`（repo 根目錄）為準；本文以下內容若有衝突，以該文件為準。第 4 節的待決事項處理如下：
>
> 1. LINE 由誰接收：**本服務 `/callback` 是唯一入口**，後端的 `/v1/line/webhook` 已移除。
> 2. 照護員身分：**以後端為準**（`/v1/users`、`/v1/bindings`、`/v1/identities/line/{id}`），本服務 SQLite 只當快取；送後端時帶真實 `user_id`、`role`，`caregiver_name` 改送匿名代號。
> 3. 意圖代碼：後端只記錄 `client_intent`，不依它路由（草案代碼照用）。
> 4. `/v1/scene` 逐字稿：後端**不保存** `utterances[].text`（未定案前從嚴）。
> 5. 主管回覆：目前仍在本服務督導頁；Open WebUI 與 `human_answered` 留待 P2 工單。
> 8. 回覆時間：預設逾時改 120 秒；LINE 聊天室改用「輸入中」動畫＋reply，不再超過 3 秒就 push。
>
> 新增：`/v1/requests/{id}` 回 `refusal_reason`、`escalate`、`citations[].quote`（原文）；`escalate=false`（範圍外、需追問）不轉督導。文字訊息免喚醒詞；緊急關鍵字在呼叫後端前處理（`src/xiaozhao/emergency.py`）。

## 1. 整體流程

```
照護員手機
 ├─ LINE 聊天室打字提問 ──────────────┐
 └─ LIFF 網頁（錄音／打字提問） ──────┤
                                      ▼
                  本服務（FastAPI，src/xiaozhao/）
   錄音：KWS 喚醒詞 → VAD 切句 → ASR → 聲紋 → 意圖（BERT 七類）→ 切輪
                                      │  只送 JSON，不送音訊
                                      ▼
                         後端（RAG／轉人工／督導）
```

- 一「輪」＝照護員說「小照你好」開始，到「小照請回答」、靜音 3 秒或下一個「小照你好」為止。
- 本服務**不送音訊**，只送逐字稿與判定結果。

## 2. 本服務呼叫後端的地方

後端介面在 `src/xiaozhao/backend.py`，只有兩個方法：

```python
class Backend(Protocol):
    def query(self, payload: dict) -> BackendResult: ...   # 單一問題
    def scene(self, payload: dict) -> BackendResult: ...   # 一整輪
```

| # | 時機 | 方法 | 程式位置 |
|---|---|---|---|
| 1 | 錄音中，某一句的意圖信心 ≥ 0.9 且屬於「規範詢問／服務請求／身體不適陳述」→ **預取**（不等整輪結束） | `query` | `pipeline.py` `_add_utterance` |
| 2a | 一輪結束：這一輪每個需要回答的意圖（規範詢問／服務請求／身體不適陳述）**各自**回答；已預取的沿用，沒有預取的各送一次（2026-10-13 起，一輪可有多個意圖） | `query`（`provisional: false`） | `pipeline.py` `_end_turn` |
| 2b | 一輪結束：送整輪紀錄（含意圖清單）；**回應不再當作回答** | `scene` | `pipeline.py` `_end_turn` |
| 3 | LIFF 網頁打字提問（在場者不同意錄音時） | `query` | `app.py` `/api/residents/{id}/text-questions` |
| 4 | LINE 聊天室傳文字訊息 | `query` | `line_service.py` |

### 2.1 送出的 JSON（目前程式實際送的內容）

**① 錄音中的預取（`query`）**

```json
{
  "client_request_id": "3f2b…（32 字元，本服務產生，每次請求不同）",
  "turn_id": 12, "utterance_id": 1, "caregiver_name": "小吳",
  "text": "阿嬤今天不想洗澡怎麼辦",
  "speaker_code": "01", "speaker_role": "照護員",
  "intent": "服務請求", "intent_conf": 0.95,
  "keywords": [], "provisional": true
}
```

**② 整輪紀錄（`scene`）**

```json
{
  "client_request_id": "…", "turn_id": 12, "session_id": "…", "caregiver_name": "小吳",
  "end_reason": "answer_keyword",
  "utterances": [
    {"idx": 0, "text": "阿嬤今天感覺怎麼樣", "speaker_code": "01", "speaker_role": "照護員", "intent": "資訊告知或交接", "intent_conf": 0.81},
    {"idx": 1, "text": "我肚子痛", "speaker_code": "02", "speaker_role": "長輩", "intent": "身體不適陳述", "intent_conf": 0.93}
  ],
  "final_intent": "身體不適陳述",
  "provisional": false
}
```

- `client_request_id`：本服務送出時產生的請求編號（2026-10-13 新增），可用來去除重複的請求。
- `caregiver_name`：照護員姓名，取自管理員建立帳號時設定的名稱（不送 LINE userId）。
- `speaker_code`：同一次錄音內的匿名說話人代號（01、02…）；照護員在確認紀錄把代號對應到身分前，`speaker_role` 為「未辨識」。
- `end_reason`：`answer_keyword`（說了「小照請回答」）／`silence`／`next_wake_word`／`session_stop`。
- `intents`（2026-10-13 新增）：這一輪的意圖清單，逐句意圖去重複後依出現順序列出：`[{"intent", "utterance_ids", "confidence", "speaker_codes", "speaker_roles"}]`；信心 < 0.5 的句子不列入。
- `final_intent`：第一個需要回答的意圖（相容舊格式）；沒有則為 `null`。
- **以問句為單位**（2026-10-14 起，`QUESTION_WINDOW=1`）：
  - 錄音的一段話會依問句切開，問句單獨一句，問句前面的陳述是它的「window」。
  - 每個需要回答的**問句各送一次 `query`**（預取時就送），`text` 為同一個 window 內的相關陳述（意圖為資訊告知或交接、身體不適陳述），加上問句，例如：「家屬今天下午會來探視，想帶水果給阿公吃，阿公有糖尿病。香蕉跟葡萄可以吃嗎？」。
  - 新增欄位：`question_utterance_id`（問句的句子編號）、`context_utterance_ids`（附上的前文句子編號）。
  - 不是問句的陳述（例如「我肚子很痛」）仍依下一點，每個意圖送一次。
  - `scene` 的 `utterances` 每句新增 `is_question`、`window_id`。
- **`scene` 的回應不再當作回答**（2026-10-13 起）：每個需要回答的意圖改以 `query` 各自回答（流程 2a），`query` 會帶 `utterance_ids`（依據句子）、`speaker_codes`，`text` 為依據句子以「；」相接。照護員看到的回答為每個意圖一行；轉督導時每個意圖各一筆。

**③ LIFF 打字提問、④ LINE 文字訊息（`query`）**

```json
{"client_request_id": "…", "text_question_id": 3, "caregiver_name": "小吳", "text": "長照補助怎麼申請", "intent": "規範詢問", "intent_conf": 0.88, "keywords": [], "provisional": false}
{"client_request_id": "…", "line_case_id": 7,     "caregiver_name": "小吳", "text": "長照補助怎麼申請", "intent": "規範詢問", "intent_conf": 0.88, "keywords": [], "provisional": false}
```

### 2.2 本服務期待收到的回應

```python
@dataclass
class BackendResult:
    request_id: str          # 後端的請求編號（之後查督導回覆用）
    status: str              # answered | awaiting_human | no_question
    answer: str | None       # status=answered 時的回答
    reason: str | None       # status=awaiting_human 時轉人工的原因（顯示給督導）
```

- `awaiting_human`：本服務會在督導頁面建立一筆待回覆請求，並帶上 `request_id`。
- `no_question`：整輪沒有需要回答的問題。

### 2.3 欄位值

- 意圖七類：`情緒安撫或閒聊`、`拒絕或抗拒`、`服務請求`、`確認或同意`、`規範詢問`、`資訊告知或交接`、`身體不適陳述`
- 說話者角色：`照護員`、`家屬`、`長輩`、`督導`、`其他工作人員`、`未辨識`
- 目前直接傳中文字串；若後端要代碼（例如 `health_inquiry`），請提供對照表。

## 3. 依後端組 API 合約串接（2026-10-14）

本服務已依後端組《小照前後端串接設計》（2026-10-03）的 ①②③ 實作 `HttpBackend`（`src/xiaozhao/backend.py`），設計見 `2026-10-14-ltc-awe-http-backend.md`、`2026-10-14-ltc-awe-async-backend.md`。

| 合約 | 本服務的用法 |
|---|---|
| ① `POST /v1/query` | 錄音偵測到問句時先送（`provisional: true`）；輪結束補送沒有預取的問題；LIFF 打字、LINE 文字提問。回 202＋`request_id` |
| ② `POST /v1/scene` | 一輪的紀錄（意圖統計、句數、時長；逐字稿可用 `BACKEND_SCENE_TEXT=0` 不送）。回 202，本服務不輪詢 |
| ③ `GET /v1/requests/{id}` | 每 0.1 秒輪詢；`answered` 顯示、`refused` 轉督導（附 `help_request_id`）、`human_answered` 顯示主管回答；錯誤或 30 秒無回覆轉督導 |

- **欄位**（`http-backend` 第 4.2 節）：
  - `request_id`：本服務產生的 UUID，同一請求重送沿用；
  - `role: caregiver`、`user_id: null`；
  - `client_intent: {code, confidence}`，`label_set_version: awe-intent-7-v1`；
  - 本服務原有的欄位（`turn_id`、`question_utterance_id`、`context_utterance_ids`…）照送，可忽略。
- **意圖代碼草案**：
  - 情緒安撫或閒聊 `emotional_support`、拒絕或抗拒 `refusal`、服務請求 `service_request`、確認或同意 `confirmation`；
  - 規範詢問 `regulation_inquiry`、資訊告知或交接 `information_handover`、身體不適陳述 `discomfort_report`。
- **驗證**：`Authorization: Bearer <BACKEND_TOKEN>`。
- **回覆目標 3 秒**（10/05 會議決議，P95）：
  - 本服務量測「送出到收到回覆」的時間，寫入 `xiaozhao_data/backend_requests-*.jsonl`；
  - `tools/backend_latency.py` 統計 P50／P95；
  - 超過 3 秒時，本服務先告知照護員「小照還在查詢」，回答到了再補上。
- **設定**（`.env`）：

  ```
  BACKEND_MODE=http
  BACKEND_URL=http://<後端主機>:8001
  BACKEND_TOKEN=<權杖>
  ```

- **本機假後端**：`python tools/fake_backend.py --port 8001`（依合約回應 202、pending、拒答，可用來對照欄位）。

## 4. 需要後端組決定或回覆的事（2026-10-14 更新）

已有答案：呼叫方式（依合約 202＋輪詢）、服務範圍（後端組已限嘉義，範圍外回「請洽 1966」）、Redis 快取（在後端組）。

1. **LINE 由誰接收**：後端組已完成 `/v1/line/webhook`，本服務也有 LINE Bot；一個官方帳號只能設定一個 webhook。建議 LINE 文字提問與綁定交後端組，LIFF（錄音、確認紀錄、我的案件、督導頁）由本服務提供，從圖文選單開啟。是否同意？
2. **照護員身分**：本服務 `user_id` 暫送 `null`。綁定是否統一用後端組的綁定碼？需要一支查詢 LINE userId 對應照護員的 API。
3. **意圖代碼**：請確認或提供代碼表（上方草案）。
4. **`/v1/scene` 是否收逐字稿**：合約原設計不含原文；本服務預設附上。是否接收？保存多久？誰能看？
5. **主管回覆**：後端組規劃 Open WebUI＋LINE 推送；本服務另有 LIFF 督導頁。轉人工後，主管在哪個介面回答？回答是否經 ③ 的 `human_answered` 回到本服務？
6. **送多少前文**：每個問句附同一 window 內的相關陳述（資訊告知、身體不適）。後端是否需要其他內容？
7. **今日狀況回報**：是否送 ⑥ `POST /v1/incidents`？（機構書面同意擱置中）
8. **回覆時間**：③ 能否支援長輪詢（`?wait=`）以縮短延遲？

## 6. 已確認的逐字稿紀錄（2026-10-13 新增）

照護員錄音後，逐字稿會在 LIFF「確認紀錄」分頁由照護員確認、督導修正並確認（人名已換成代號）。**只有督導確認過的紀錄**才會提供給後端，供存入知識庫。

```
GET /api/export/records?after_seq=<上次取到的最後編號，第一次用 0>&limit=<1～500，預設 100>
Authorization: Bearer <EXPORT_TOKEN>    ← 由本服務另外提供，請勿放進版控
```

回應：

```json
{
  "records": [
    {
      "seq": 12,
      "session_id": "c0ffee…",
      "resident_alias": "住民 A",
      "confirmed_at": 1760342400.0,
      "speakers": {"01": "照護員", "02": "長輩"},
      "sentences": [
        {"start_ms": 2820, "end_ms": 6820, "speaker": "01", "role": "照護員",
         "text": "阿嬤今天感覺怎麼樣", "intent": "資訊告知或交接", "intent_owner": null},
        {"start_ms": 7240, "end_ms": 9100, "speaker": "02", "role": "長輩",
         "text": "我肚子痛", "intent": "身體不適陳述", "intent_owner": "長輩"}
      ]
    }
  ],
  "next_after_seq": 12
}
```

- **增量抓取**：後端記住 `next_after_seq`，下次帶入 `after_seq`；`records` 為空表示目前沒有新的。
- 每筆是一「輪」；`seq` 只增不減，同一筆不會改變內容（確認後即鎖定）。
- `speaker` 是同一次錄音（`session_id`）內的匿名代號，不同錄音之間不代表同一人；`role` 為照護員或督導確認的身分。
- 不含：照護員 LINE ID、音訊、系統修正前的原始輸出。
- 保存：本服務在後端第一次取走後再保留 30 天；確認後一直未被取走的，最長保存 90 天。請定期抓取。
- 錯誤：權杖錯誤 401；本服務未設定權杖（匯出未啟用）404；參數錯誤 400。
